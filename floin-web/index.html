The Problem

Existing systems show static 2D maps. People cannot see how water will flow, how deep it becomes, or which buildings/roads will be affected.

  • Flat choropleths hide terrain
  • No time-based water propagation
  • No building / road impact

The Solution — FLOIN

Rainfall + geography → numerical simulation → interactive 3D terrain with water propagation, depth shading & infrastructure overlay.

  • SCS Curve Number runoff
  • D8 flow direction & accumulation
  • Three.js time-step flood extent

Interactive 3D Flood Simulation

Procedural Chennai terrain displaced from SRTM DEM structure • Buildings extruded from buildings.geojson • Water plane driven by SCS-CN + time routing. Drag to orbit, scroll to zoom.

Algorithms Used

Rainfall → Runoff

SCS Curve Number

Estimates surface runoff from P and CN (soil/land use).

Flow Direction

D8 Algorithm

Steepest slope to 1 of 8 neighbors → direction code.

Flow Accumulation

Grid accumulation

Identifies drainage convergence & watershed cells.

Flow Routing

Terrain-based routing

Moves water between cells per direction.

Flood Depth

Water balance

Depth = accumulated volume − terrain capacity.

Flood Extent

Depth threshold

Marks cells where depth > threshold as flooded.

SCS Curve Number

S = (25400 / CN) − 254
if P ≤ 0.2S:  Q = 0
else:        Q = (P − 0.2S)² / (P + 0.8S)

Why QGIS + Why not alternatives?

QGIS gives one free, open workbench for CRS, clipping, cleaning & visual QA before PostGIS. You could do it in Python (GDAL/Rasterio/GeoPandas), GRASS, SAGA, ArcGIS or Earth Engine — but you'd write more code or pay for licenses. QGIS lets you see that roads/buildings/DEM actually align before simulation.
